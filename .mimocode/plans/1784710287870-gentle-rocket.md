# Feature: Cross-Hierarchy Alignment Links (Objective↔Goal, Objective↔KR)

## Problem

The alignment section in the objective inspector modal currently shows "Choose Objective" with an empty dropdown. The user wants:
- **"Add parent link"** → "Choose Goal" → dropdown lists existing Goals
- **"Add child link"** → "Choose Key Result" → dropdown lists existing Key Results

The current `AlignmentEdge` model only links objective↔objective. This feature requires new cross-hierarchy links between Objective↔Goal and Objective↔KR.

## Design

### New Model: `ObjectiveAlignmentLink`

A new table that stores alignment links between an Objective and a Goal or Key Result.

**File:** `src/models.py` (add after `AlignmentEdge`)

```python
class ObjectiveAlignmentLink(SQLModel, table=True):
    """Additional alignment link between an Objective and a Goal or Key Result."""
    __tablename__ = "objective_alignment_link"
    __table_args__ = (
        Index("ix_obj_align_obj_linked", "objective_id", "linked_entity_type", "linked_entity_id", unique=True),
        {"extend_existing": True},
    )
    id: Optional[int] = Field(default=None, primary_key=True)
    objective_id: int = Field(foreign_key="objective.id", index=True)
    linked_entity_type: str = Field(...)  # "goal" or "key_result"
    linked_entity_id: int = Field(...)    # FK to goal.id or key_result.id
    direction: str = Field(...)           # "parent" (linked entity is parent) or "child" (linked entity is child)
    created_at: datetime = Field(default_factory=utc_now_naive)
    created_by: Optional[str] = None
```

**Why a new model instead of extending `AlignmentEdge`:**
- `AlignmentEdge` has hard FKs to `objective.id` for both parent_id and child_id
- The new model needs to reference Goal or KR — different tables with different PKs
- Polymorphic FKs (`linked_entity_type` + `linked_entity_id`) are the cleanest approach
- Keeps existing objective↔objective alignment untouched
